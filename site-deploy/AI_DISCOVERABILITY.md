# Search and AI discoverability

Reviewed against official vendor documentation on 2026-09-30. This is the
public website contract; crawl access never guarantees indexing or citation.

## Public content and identity

The canonical identity is Terento, <https://terento.app/>, with source at
<https://github.com/VooZ2/terento>. `site/metadata.json` inventories 30 indexable
pages: Home, About, Download, Compatibility, and the installation Guide, each
in six languages. Legal and Privacy deliberately remain `noindex,follow`;
404 and the legacy supported-watches fallback remain noindex. Do not add thin
per-device/provider pages or invent support claims to increase the page count.

Initial HTML contains the product description, macOS/Apple Silicon scope,
provider cards, FAQ, instructions, troubleshooting and native navigation links.
Compatibility cards are generated by `scripts/build-compatibility-pages.py`
from `site/compatibility/public-models.snapshot.json`. The existing refresh
workflow obtains this allowlisted projection from the authoritative public
API. JavaScript refreshes and filters it; neither snapshots nor search rules
change device approval or installation authorization. Snapshot counts can age
between publications. The current static representation needs no new SSR layer.

## Crawler policy

`site/robots.txt` is the public-host source. Its wildcard group permits public
pages/assets by default and excludes admin/internal/API/diagnostic/preview/lab/test
paths. Keep one shared group: adding a bot-specific group without copying the
exclusions can override the wildcard policy. Robots rules are voluntary crawl
instructions, not authentication and not reliable removal from search results.
Keep authentication on private resources and noindex on accessible utility pages.
Legal/Privacy must remain fetchable so their noindex can be read.

| Agent/token | Purpose and intended public-page access |
| --- | --- |
| OAI-SearchBot | ChatGPT Search discovery; allowed |
| ChatGPT-User | User-initiated retrieval; allowed; OpenAI says robots rules may not apply |
| GPTBot | Model training; existing public access retained, independent of Search |
| Claude-SearchBot | Search discovery; allowed |
| Claude-User | User-directed retrieval; allowed |
| ClaudeBot | Model training; existing public access retained |
| Googlebot | Google Search, including its AI features; allowed |
| Google-Extended | Product token for Gemini training and grounding uses; existing access retained |
| Bingbot / other crawlers | Public pages allowed under the same exclusions |

Google-Extended has no independent HTTP user agent. It controls future Gemini
training and grounding in Gemini Apps and Grounding with Google Search on
Vertex AI; it does not determine Google Search inclusion or ranking. Review
its combined training/grounding implications before changing it. No dedicated
HTTP probe pretending to be Google-Extended proves that policy works.

## Canonicals, sitemap and IndexNow

`site/metadata.json` and `scripts/normalize-site-metadata.py` own titles,
descriptions, canonical URLs, language alternates and social metadata. Canonicals
use HTTPS, the apex domain and trailing slashes; UTM/query strings never enter
them. Directory redirects and the supported-watches alias lead to canonical
pages. Explicit `index.html` aliases retain the directory canonical; uppercase
unknown paths return 404 rather than creating another content inventory.

`scripts/generate-sitemap.py` owns `site/sitemap.xml`; its inventory excludes
noindex utilities, redirects, APIs and private paths. Thirty URLs are well below
[sitemap limits](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).
Meaningful content fingerprints and reliable Git history govern `lastmod`;
do not insert the generation time. The same manifest drives IndexNow delta
selection. Preserve `.github/indexnow/site-state.json`, accepted/pending
fingerprints, submission timestamps, live verification and the server-only key.
A successful submission is not evidence of indexing. Adding robots/llms does
not require adding these files as HTML pages or submitting duplicate notifications.

## Structured data and supplemental index

`scripts/normalize-structured-data.py` synchronizes Home/Download application
facts with published release metadata and visible FAQ content. Organization,
WebSite and SoftwareApplication share canonical identities; price zero reflects
the free product. No invented reviews/ratings are allowed. Guide breadcrumbs
are generated in `scripts/build-guide-pages.py` for all six locales.
`scripts/validate-structured-data.py` recursively validates nested entities,
arrays and graphs. Keep existing source/output parity and visible-content tests.

Existing FAQPage remains a factual description of the visible FAQ. Do not claim
Google FAQ rich results: Google's [June 2026 documentation update](https://developers.google.com/search/updates#june-2026)
records their removal. No new schema type is needed for this audit.

`scripts/generate-llms.py` derives `site/llms.txt` from existing page metadata,
with the official repository link. It is a supplemental public index, not a
vendor requirement or a replacement for HTML, robots or sitemap. The reviewed
vendor documentation does not establish universal consumption or ranking gains.

## Serving boundaries and analytics

`site-deploy/Caddyfile` preserves public HTML access and applies noindex to JSON
metadata while keeping it available to app/browser clients. It keeps the
existing error-page noindex and security/cache headers. No CSS or JavaScript
was changed by this audit; asset versions therefore stay unchanged.

The API hostname and production Cloudflare settings are separate operational
boundaries. Public-host robots do not apply to `api.terento.app` or testing
hosts. Operator edge files under ignored `internal/infra/` are not shipped by
a website image. API-wide noindex and a restrictive API robots response require
an owner-reviewed edge change; preserve Cloudflare Access and the origin guard.
Staging must retain its existing noindex/no-tracking configuration.

`site/privacy-consent.js` preserves allowed UTM strings in incoming URLs and
on relevant navigation/download links. Tests cover `chatgpt.com`, `claude.ai`,
`gemini.google.com`, Bing and an arbitrary source without application hardcoding.
Referrers can be absent and UTM values are untrusted attribution, not verified
crawler identity. Umami IP exclusions, collection behavior and storage policy
remain unchanged. Use the existing dashboard's sources/referrers/campaigns;
no fingerprinting or new crawler telemetry is introduced.


The existing SEO runner includes the llms parity and discovery boundary tests;
CI and image publication already run that runner. The full site suite also
runs sitemap/IndexNow regressions, compatibility snapshot growth, Guide parity,
visible-FAQ/schema contracts and analytics tests. Test changes to serving rules
with Caddy as well as source contracts before publication.

When vendors change behavior: read their current official pages, record the
review date, distinguish training from retrieval, adjust policy only within
owner intent, and test public access plus private exclusions for every agent.
After a separately authorized deployment, fetch robots, sitemap and representative
pages with headers and inspect canonical/noindex/content. Compare all sitemap
URLs against live pages. Use real verified crawler observations to assess WAF
access; user-agent spoofing from a developer machine cannot establish it.
